1项目结论与范围

先定范围：这是一套内部机制，不是一个外部联盟系统。

本项目只服务 GARVEE 内部商品开发团队。MVP 不建设完整的外部联盟／分销系统，而是在现有官网发布能力上补齐四段能力：内部写稿协作、编辑与发布、自然搜索归因、销售激励台账。
  1. 商品开发提交 SEO 文章提供商品知识、真实场景与初稿，不能直接发布
  2. SEO／内容负责人统一编辑、翻译复核与发布原文定稿后再启动多语言，各语言分别复核
  3. 系统识别自然搜索带来的订单并完成唯一归属按正式自定义渠道组判定，一单最多一条有效归属
  4. 按合格净商品销售额生成内部激励明细经退款观察期后进入月度薪酬／奖金流程

已确定 vs 待业务评审

✓ 已确定
  • 仅限 GARVEE 内部员工参与
  • 商品开发负责商品知识与初稿，不能直接发布
  • 文章审核后发布，并建立唯一跟踪标识
  • 激励基数为合格净商品销售额（比例待定，见第 6 节）
◷ 待业务评审
  • 总激励池比例与各角色分配（5% 方案 vs 系统 1%–3% 口径，存在冲突）
  • 归因窗口暂按 30 天
  • 净销售额需排除的财务扣除项
  • 退款观察期暂按 45 天
  • 暂按月进入内部薪酬／奖金流程

2要解决的问题

知识已经存在，缺的是一条把它变成资产的链路。

GARVEE 已经拥有大量商品知识、用户场景经验和品类理解，但这些知识往往停留在商品开发过程与个人经验中，没有持续转化为能被 Google 等搜索引擎获取的内容资产。

商品专业知识 → 高质量内容 → 自然搜索流量 → 可归属销售 → 额外激励

本项目要建立的就是这条简单、可核查的业务链路。它买下的不是"多写几篇文章"，而是把已经存在的专业能力变成长期可复用的增长资产。

3参与边界与核心原则

这一节是整套机制能否被接受的前提：不能被理解成"变相加工作"。

自愿参与 不新增基础 KPI 不参加不影响绩效与薪酬 参与不等于保证有奖金 只有产生符合规则的销售才计提
事项规则
是否参加员工自主选择，不强制
是否属于基础岗位职责否，属于额外参与机会
不参加是否影响绩效／薪酬否
参与后是否保证有奖金否；只有产生符合规则的销售才计提
员工需要负责选题确认、商品专业内容、初稿、按审核意见修改
员工不需要负责SEO 技术配置、官网发布、翻译执行、数据判断、订单归因、奖金计算
设计意图：员工能看到三件事就够了 —— 我可以不参加；如果参加，我只做自己最擅长的那部分；如果内容真的产生销售，我能拿到清晰、可追踪的额外收益。

4为什么值得做

三方视角各自的收益，决定这套机制能否真正跑起来。

对公司

  • 沉淀可持续的自然搜索内容资产
  • 减少对单一付费流量的依赖
  • 以结果激励替代纯固定投入

对商品开发负责人

  • 获得团队自然销售、TOP 商品／品类、参与度等经营数据
  • 获得新的团队经营抓手
  • 同时获得团队结果激励

对商品开发员工

  • 多一条自愿的额外收入渠道
  • 用最熟悉的商品知识创造额外收益
  • 拿到最高激励权重

为什么作者拿最高

商品开发是否愿意持续参与，是项目能否跑起来的关键。作者获得 3.8%，占总激励池 76%，确保真正承担额外内容生产的人拿到绝对大头；其余角色只作为协同激励，不改变作者的主体地位。

口径冲突，需在评审时消解：业务方案为"总池 5%，作者 3.8%"；产品 MVP 文中写作"按合格净商品销售额的 1%~3% 计提"。两者无法同时成立 —— 作者的 3.8% 已超过 3% 上限。建议按下列方式收敛，而不是保留两套数字：
  • 若采纳 5% 池：系统只配置"单篇作者 3.8% + 负责人 0.3% + 编辑 0.6% + SEO 0.3%"，MVP 中删除 1%~3% 的表述。
  • 若采纳 1%~3%：需重新给出分配表（作者 3.8% 必须下调），并重算占池比例与管理层投入产出模型。
  • 无论哪种：比例必须参数化可配置，并把使用的比例版本写入每条激励记录，后续调比例不追改历史结果。
应计激励 = 合格净商品销售额 × 对应角色比例（比例版本随记录固化）

7内容生产与发布流程

原则：商品开发只做专业内容，编辑管质量，SEO 管增长，发布、归因与结算不增加商品开发的操作负担。

业务流转（7 阶段）

  1. SEOSEO 选题基于搜索需求与商品机会建立选题池，也接受商品开发主动提案
  2. 商品开发撰写提交自愿领取／确认选题，提交初稿、商品事实与场景依据
  3. 编辑编辑审核审核事实、结构、表达、可读性与合规；退回必须说明原因
  4. SEOSEO 优化优化搜索意图、关键词、标题结构、内链与商品链接
  5. 编辑 / 市场翻译与本地化原文通过后机器初译并人工复核，需要时分语言发布
  6. SEO / 内容官网发布发布到官网内容区并记录正式 URL
  7. SEO / 数据 / 财务效果监测与结算记录自然访问、订单、合格销售额及激励结果

系统侧动作（对应 6 步）

  1. 选题分配SEO／内容负责人创建选题并指定商品与目标市场
  2. 撰写提交商品开发提交初稿与商品依据，形成新版本记录
  3. 编辑审核审核事实、结构、搜索意图与合规性
  4. 翻译复核机器初译 + 人工本地化复核
  5. 官网发布发布并回写正式 URL 与文章编号
  6. 效果监测记录索引、自然访问、订单与激励

内容状态（仅保留这 5 个主状态）

草稿 待审核 退回修改 待发布 已发布

退回规则：审核人必须填写退回原因；商品开发修改后形成新版本并重新进入编辑审核。每次提交、退回、批准、发布、下线均记录人员与时间。

发布门槛：只有审核通过的版本可以发布，商品开发没有官网发布权限。原文先定稿再启动翻译，各语言分别复核发布。

8选题与内容质量机制

不依赖员工自由发挥：SEO 先建统一选题池，商品开发可提案，由 SEO 判断真实搜索价值。

选题来源典型方向
搜索需求How-to、Buying Guide、Comparison、选购、安装、维护、Troubleshooting、场景问题
商品机会重点新品、高库存、重点品类、有搜索需求的 SKU、专业壁垒高的产品
商品开发提案员工认为用户会真实搜索的问题、场景或产品差异点

编辑把关：内容是否准确、好读、有用

事实核验、结构、表达、合规性；依据不足直接退回。

SEO 把关：用户能否搜到

搜索意图匹配、关键词与标题结构、内链与商品链接、可索引性。

低质量、无搜索价值或事实依据不足的内容不进入正式发布。第一阶段的目标不是文章数量，而是跑出真实案例。

9归属规则：自然搜索识别与唯一归属

为减少争议：唯一归属、规则提前确定、历史结果可追溯。

  1. 搜索进入文章首次落地到已发布、可索引的文章页
  2. 核对正式渠道使用 GARVEE 正式自定义渠道组判定自然搜索
  3. 绑定文章与员工记录文章编号、员工编号与进入时间
  4. 核对有效订单暂按进入后 30 天内支付成功的订单
  5. 检查唯一归属同一订单不得重复计入其他激励体系
  6. 生成激励记录写入唯一订单归属、计提金额与规则版本

归因口径

  • 自然搜索判定：使用 GARVEE 正式自定义渠道口径；默认渠道组、Source / Medium 仅用于辅助审计，不作为计提依据。
  • 归因窗口：暂按 30 天。
  • 入口选择：采用"窗口内最近一次合格自然文章入口"。
  • 唯一归属：同一订单在本激励体系内只能有一条有效主归属，避免一单多奖。
  • 冲突处理：如订单已进入其他佣金或人工激励体系，先冻结复核，不自动重复计提。
  • 口径边界：归因销售属于"可归属自然搜索销售额"，不直接等同于全部新增销售额，对外表述不得混用。

10合格净商品销售额与退款

激励基数用净商品销售额，不是订单总支付金额。

项目口径
计入实际成交商品的净额（去除取消、退款、商品退款后）
初期排除取消、退款、商品退款、礼品卡等非实际商品收入
暂不进入基数税费、运费等非商品收入（最终以财务确认口径为准）
退款观察期暂按 45 天
发放前退款直接减少应发金额
发放后退款形成冲正记录，在后续批次抵扣
留痕要求原始计提、退款与冲正记录全部保留，不得覆盖或删除
待财务确认：净商品销售额的具体扣除项清单；低毛利商品是否需要设置激励保护线（如低于某毛利率不计提或封顶）。

11产品方案（MVP）

最小可用范围：把"写稿—审核—发布—归因—台账"做成一条闭环，不做多余功能。

必须具备的能力

模块能力
内容任务选题分配、初稿提交、版本记录、退回意见、状态流转
编辑发布原文审核、机器初译、本地化复核、发布地址回写、下线
跟踪归因唯一标识、自然入口记录、订单匹配、重复归属检查
激励台账计提、观察期、退款冲正、冻结复核、月度导出
内部看板员工查看本人文章与激励；负责人查看团队进度与效果

唯一标识设计

标识用途
员工编号确认文章负责人与激励归属人
文章编号贯穿草稿、翻译、发布地址与数据分析
自然入口编号记录一次合格自然搜索进入
订单编号防止订单重复归属
激励事件编号关联计提、退款、冲正与发放记录

系统关键规则

  • 只有审核通过的版本可以发布；商品开发无官网发布权限。
  • 每次提交、退回、批准、发布、下线都记录人员与时间。
  • 同一订单最多存在一条有效激励记录（数据库层面强约束，而非仅流程约束）。
  • 归因规则版本与激励比例版本必须写入激励记录，后续改规则不追改历史结果。
  • 员工只查看本人明细；负责人、技术／数据、财务按职责查看全量数据。
仍需产品确认：官网文章最终发布到哪个现有内容栏目、由哪个后台或接口承接；这决定发布回写与 URL 跟踪的实现方式。

13试点建议：先自愿小范围跑通

第一阶段不追数量，只求跑出真实案例。

建议项第一阶段
参与方式自愿报名
参与人数5–10 名商品开发
内容规模约 20–30 篇高质量文章
观察周期建议至少 2–3 个月起步

14验收标准

可逐条验收，避免"流程做出来了"就算完成。

  • 商品开发可在一个入口完成领取、撰写、提交和查看退回意见。
  • SEO／内容负责人可完成审核、翻译复核、发布和下线。
  • 每篇已发布文章都有稳定且唯一的文章编号与负责人。
  • 正式自然搜索报表使用 GARVEE 指定自定义渠道组。
  • 任一订单不能生成两条有效激励记录。
  • 退款可自动形成冲正，且原始记录可追溯、不可覆盖。
  • 财务／薪酬可按月导出员工、订单、计提、冲正与应发金额。

15待评审决策清单

这 6 项确认后，即可拆解产品原型、接口和研发任务。

  • 激励比例口径（优先）：总池 5%（作者 3.8% / 负责人 0.3% / 编辑 0.6% / SEO 0.3%）与系统"1%~3%"二者择一，并确定参数化方案。
  • 参与原则：商品开发自愿参与、不进入基础 KPI、不影响正常绩效与薪酬。
  • 归因规则：30 天归因窗口与"窗口内最近一次合格自然文章入口"是否确认。
  • 财务口径：合格净商品销售额的扣除项；低毛利商品是否设激励保护线。
  • 退款与发放：45 天退款观察期；激励通过工资、奖金还是专项奖励发放，及月度节奏。
  • 发布承接：官网文章最终发布到哪个现有内容栏目，由哪个后台或接口承接。
项目最终要验证的不是"能不能把流程做出来"，而是这套利益机制能否让商品知识持续转化为自然搜索销售 —— 让员工愿意参与、负责人愿意推动、编辑和 SEO 愿意协同，并形成公司可以长期复制的内容增长能力。
